# CleanHtml

CLI-скрипт для очистки локальных HTML-файлов документации и сохранения полезного содержимого в Markdown.

Скрипт рассчитан на большие наборы документации: много маленьких `.html` / `.htm` файлов обрабатываются параллельно через `ProcessPoolExecutor`.

## Что делает

- на вход принимает HTML-файл или директорию;
- если передана директория, рекурсивно ищет `.html` и `.htm`;
- удаляет навигационную обвязку, шапки, футеры, скрипты, стили и служебные блоки;
- сохраняет основной текст, заголовки, списки, таблицы и code blocks;
- конвертирует результат в Markdown;
- создаёт результат рядом с исходником.

## Имена выходных файлов

Для одного файла:

```text
page.html -> page_clean.md
```

Для директории:

```text
docs/ -> docs_clean/**/*.md
```

Структура подпапок сохраняется.

## Установка

Отдельная установка зависимостей не нужна, если запускаешь через `uv`.

Скрипт содержит metadata с зависимостями:

- `beautifulsoup4`
- `lxml`
- `markdownify`

Первый запуск может быть медленнее, потому что `uv` скачает зависимости.

## Быстрый запуск

Windows:

```bat
uv run python clean_html.py "F:\Coding\ai_allowed\NanoComrade\externals_cad_docs\nanoCAD" -w
```

С явным количеством процессов:

```bat
uv run python clean_html.py "F:\Coding\ai_allowed\NanoComrade\externals_cad_docs\nanoCAD" -j 8 -w
```

Один HTML-файл:

```bat
uv run python clean_html.py "F:\docs\page.html" -w
```

## Основные флаги

```text
-l,  --links keep|drop          Оставлять markdown-ссылки или только текст ссылок.
-a,  --attachments keep|drop    Оставлять или удалять картинки, видео и файловые вложения.
-j,  --jobs N                   Количество параллельных процессов.
-fe, --fallback-encoding ...    Дополнительные кодировки для не-UTF-8 HTML.
-w,  --overwrite                Перезаписывать уже созданные .md файлы.
-q,  --quiet                    Минимум вывода.
-k,  --keep-related             Не удалять related/parent/topics/links-секции.
```

По умолчанию:

```text
--links keep
--attachments drop
--jobs 0
```

`--jobs 0` означает auto: использовать все доступные логические CPU, но не больше количества HTML-файлов.

## Про прогресс

Скрипт не печатает информацию по каждому файлу. Прогресс обновляется только при изменении целого процента:

```text
Прогресс:  42% (4235/10000) | записано: 4235 | пропущено: 0 | ошибок: 0
```

Это сделано специально, чтобы консольный вывод не замедлял обработку большого числа маленьких файлов.

## Что такое `--keep-related`

По умолчанию скрипт удаляет секции вроде:

- `Related Concepts`
- `Related Reference`
- `Parent topic`
- `Topics in this section`
- `Ссылки`
- `Условные обозначения`

Для RAG/индексации такие блоки часто являются шумом: они дублируются на тысячах страниц и ухудшают качество поиска.

Если эти секции нужны, запускай так:

```bat
uv run python clean_html.py "F:\docs" --keep-related -w
```

Короткого флага для этой опции нет намеренно: опция редкая и сильно влияет на качество очистки.

## Рекомендации по скорости

Обычно достаточно запустить без `-j`:

```bat
uv run python clean_html.py "F:\docs" -w
```

Скрипт сам выберет количество процессов по числу CPU.

Если во время работы сильно нагружен диск или компьютер становится неотзывчивым, уменьши число процессов:

```bat
uv run python clean_html.py "F:\docs" -j 4 -w
```

Если CPU загружен не полностью, можно попробовать указать больше процессов вручную:

```bat
uv run python clean_html.py "F:\docs" -j 12 -w
```

## Кодировки

Для русской офлайн-документации часто встречается `windows-1251` / `cp1251`.

По умолчанию скрипт пробует:

```text
utf-8-sig
utf-8
cp1251
cp866
системную кодировку
```

Дополнительные кодировки можно указать так:

```bat
uv run python clean_html.py "F:\docs" -fe cp1251 cp866 koi8-r -w
```

## Повторный запуск

Если выходной `.md` уже существует, по умолчанию файл пропускается.

Чтобы пересоздать результаты:

```bat
uv run python clean_html.py "F:\docs" -w
```

## Ограничения

Скрипт лучше всего подходит для локальной HTML-документации:

- API docs;
- Doc-O-Matic;
- Autodesk/OARX-подобная документация;
- Doxygen-подобные страницы;
- offline help.

Для произвольных веб-страниц результат может быть хуже, потому что у сайтов сильно отличается структура HTML.

Скрипт не исполняет JavaScript. Если полезный контент появляется только после выполнения JS, он не будет извлечён.
